## Подтверждённые разрывы и ограничения контекста

1. **Городская CTA использует другой ключ.** В новой сессии переход из `/almaty` через нижнюю CTA не устанавливает `selection.city`: `slug=almaty` проверяется как направление, а город принимается только из `city`. При существующей cookie старый город может сохраниться, поскольку `fromQuery` не очищает его при отсутствии `query.city`. Cookie живёт 30 дней. Основание: [defaults и cookie](/C:/Users/Admin/Documents/sertificate/composables/useLmsSelection.ts:68), [fromQuery](/C:/Users/Admin/Documents/sertificate/composables/useLmsSelection.ts:98). Это вывод из кода, не результат прогона браузера.

2. **Переключатель города не отражает город из query или cookie.** `currentCity` читает только `route.params.city` либо городской slug из `route.params.course`. Поэтому на `/courses/{id}?city=almaty` и `/program-selection?city=almaty` выбор города этим компонентом не отображается. При изменении города вне городского URL он ведёт на `/{slug}`; на городском URL заменяет первый сегмент. В обоих случаях `router.push` получает только путь, без query. Основание: [определение города](/C:/Users/Admin/Documents/sertificate/components/CitySwitcher.vue:12), [смена города](/C:/Users/Admin/Documents/sertificate/components/CitySwitcher.vue:28).

3. **Каталог и часть вторичных ссылок не переносят контекст.** Подтверждены: каталог → карточка ([158](/C:/Users/Admin/Documents/sertificate/pages/courses/index.vue:158)); городской `CoursePage` → «программа» ([661](/C:/Users/Admin/Documents/sertificate/components/CoursePage.vue:661)); карточка LMS → «Подробнее о направлении» ([144](/C:/Users/Admin/Documents/sertificate/pages/courses/[id].vue:144)); общая оболочка LMS → каталог/подбор/кабинет ([18](/C:/Users/Admin/Documents/sertificate/components/lms/LmsShell.vue:18)). Это потеря параметров конкретного перехода; наличие сохранённого выбора в cookie не доказывает, что принимающая страница его использует.

4. **Выбранный формат не фиксирует версию курса.** Подбор проверяет варианты по языку и формату, но ссылка результата не передаёт `versionId`; карточка автоматически учитывает язык, не `query.format`. При нескольких версиях возможна другая версия, чем ожидал посетитель. Условия возникновения: у курса несколько версий одного языка с разными форматами. Основание: [подбор](/C:/Users/Admin/Documents/sertificate/pages/program-selection.vue:48), [ссылка](/C:/Users/Admin/Documents/sertificate/pages/program-selection.vue:236), [выбор](/C:/Users/Admin/Documents/sertificate/pages/courses/[id].vue:29).

5. **Город пока не доказывает локальную доступность обучения.** Он включён в ключ запроса/аналитику подбора и передаётся в следующую ссылку, но API-запрос запрашивает программу по id, а клиентский фильтр учитывает только язык, формат и открытый набор. В карточке нет выбора версии по городу. Роль и отрасль также передаются, но не участвуют в этом фильтре. Нельзя на основании нынешнего кода утверждать, что результат уже соответствует расписанию, адресам или наличию группы в городе. Основание: [lookup](/C:/Users/Admin/Documents/sertificate/pages/program-selection.vue:34), [filter](/C:/Users/Admin/Documents/sertificate/pages/program-selection.vue:48), [текст результата](/C:/Users/Admin/Documents/sertificate/pages/program-selection.vue:210).

## Критерии приёмки для отдельной будущей задачи

Это план проверки и возможных исправлений, а не внесённые изменения.

1. В чистой сессии пройти `/` → `/almaty` → подбор → конкретная программа. В каждой точке проверить название города, параметр URL/согласованное состояние и отсутствие другого города из предыдущей сессии. Повторить со старой cookie другого города.
2. Проверить одинаковый смысл города после переходов через шапку, каталог, городское направление, городской формат, вторичные CTA, браузерные «назад/вперёд» и перезагрузку. Явная смена города должна иметь понятный результат для выбранного курса.
3. Для программы с двумя версиями одного языка и разными форматами пройти подбор каждого формата. Открытая версия, показанные условия и `versionId` записи/заказа должны соответствовать выбранному варианту; если варианта нет, требуется понятное объяснение и следующий шаг.
4. Определить продуктовый смысл города: информационная привязка, фильтр доступности, место очного обучения или сочетание этих значений. До подключения данных расписания и адресов интерфейс не должен выдавать наличие `city` за подтверждённый набор в городе.
5. Для анонимного посетителя проверить вход/регистрацию/подтверждение почты и возврат к исходному курсу или оплате с контекстом. Для существующего слушателя проверить кабинет → своё обучение → урок → сохранённый прогресс после обновления.
6. В разрешённой тестовой среде проверить платный индивидуальный сценарий и сценарий организации: версия → заказ → подтверждённый статус → назначение → доступ. Не создавать реальные платежи ради проверки навигации. Соответствие организационной записи выбранной версии оценить отдельно.
7. Проверить проверку знаний, сохранение результата и переход в документы; скачать файл только при его готовности. Пустые назначения, приостановленный набор, 401, недоступный API, отсутствующая версия и ещё не готовый документ должны показывать понятное продолжение.
8. Повторить ключевые пути на русском и казахском, мобильном и широком экране, клавиатурой. По каждому шагу записать: видимый CTA, фактический URL, выбранные город/курс/формат, состояние интерфейса и результат. Снимок красивого экрана не заменяет такой маршрутный протокол.
