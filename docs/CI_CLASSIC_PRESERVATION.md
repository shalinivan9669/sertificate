# Защита HomePageClassic в CI

Условие владельца — сохранить существующую главную HomePageClassic и её публичный маршрут, не заменять их `nuxt-redesign`. Проверка добавлена в существующий Quality workflow без дополнительной сборки Nuxt, загрузки полной истории Git или генерации нового эталона из проверяемого кода.

## Два независимых уровня

`tests/classic-design.test.mjs` входит в обычный `npm test`. Он вычисляет Git blob ID после единственной нормализации CRLF → LF и сравнивает два реальных файла с фиксированными значениями из указанного владельцем commit `413ad4a34e53203f39df3946962903f51caf16a0`:

| Файл | Зафиксированный Git blob |
| --- | --- |
| `components/HomePageClassic.vue` | `a1ff0776d2d4c98297b0050b553c35ccbe00fba4` |
| `pages/index.vue` | `5d5710fa6eb31021139bb1a15b0fcf3e026072de` |

Эти значения сверены через `git rev-parse <commit>:<path>` и `git hash-object <path>`. Защита охватывает весь компонент и фактическую страницу, которая импортирует и отображает его. Она работает при стандартном shallow checkout GitHub Actions. Команды автоматического обновления эталона нет. Намеренное изменение этих файлов требует отдельного рассмотрения изменения дизайна; переписывание контрольной суммы по HEAD не является исправлением регрессии.

`tests/classic-browser.mjs` выполняется первым в последовательном `tests/run-core-browser.mjs`. Текущий launcher включает шесть suites: classic/auth/contact/leadContext/learner/staff; проверка передачи контекста добавлена после contact. Используется уже собранный Node-артефакт и один изолированный локальный сервер. Никаких дополнительных параллельных сборок или записей в учебную БД classic-сценарий не делает.

Браузер открывает `/` и `/kk` на 1440×1000, 768×1024, 390×844 и 360×800 после гидратации. Проверяются HTTP 200, один ожидаемый локализованный H1, видимые CTA, девять исторических ссылок направлений, шесть карточек форматов, загрузка логотипа, отсутствие необработанных JS ошибок и горизонтальной прокрутки. Выбранные computed CSS значения взяты из уже снятого эталона 413ad4a: белый hero, его border/radius/padding, размер и цвет H1, цвет/radius/padding основной кнопки, gap и число колонок обеих сеток. Такой тест обнаруживает, например, потерю Tailwind стилей, замену brand accent, изменение md breakpoint или растягивание карточек за viewport, даже если исходный Vue-компонент не менялся.

Сохраняются восемь снимков и измерения `artifacts/classic-browser/report.json`. Existing CI публикует `artifacts/` при ошибке. Сетевые запросы за пределы тестового origin заблокированы; используются установленные в среде системные fallback fonts. Тест не подменяет CSS страницы и не меняет интерфейс для получения проходящего результата.

## Границы

Это автоматическая защита исходной главной плюс проверка конкретных визуальных и адаптивных свойств текущего артефакта. **Pixel-diff не выполняется.** Снимки служат материалом для просмотра. Здесь не сравниваются растеризация текста, фактический font face, абсолютная высота страницы, положение шапки/подвала и каждый элемент сайта. Разрешённые изменения навигации, доступности футера и новых учебных страниц не заблокированы фиксацией всей темы.

Ранее выполненное сравнение восьми вариантов исходной и новой главной в одной локальной среде описано в `docs/VISUAL-ACCESSIBILITY-QA.md`. Его Windows/Chrome снимки и геометрия не объявляются переносимым Linux pixel baseline. Для полного автоматического screenshot-diff нужен отдельно рассмотренный эталон в закреплённой ОС/версии Chromium с доступными лицензированными шрифтами и явным процессом одобрения изменений; автоматическое создание эталона из текущей ветки не удовлетворяет этому требованию. Человеческая приёмка дизайна остаётся отдельным условием handoff.
