Эта матрица дополняет исходную [карту маршрутов и API](2026-09-14-route-audit.md). Исходная карта фиксирует проблемы **до** исправлений; текущая матрица отличает изменение кода от проверки работающего экрана. Это аудит исходников и инженерная проверка, не исследование с пользователями.

Проверены все 62 Vue-файла `pages/`, используемые ими общие шаблоны и соответствующие API-контракты. В публичной маршрутной политике 558 индексируемых локализованных URL; снимки представителей шаблона не означают, что вручную открыты все 558 адресов. Страницы назначения, заказа, попытки и документа имеют дополнительное пространство динамических ID.

## Как читать матрицу

- **Изучено** — прочитан действующий маршрут/компонент и его контракт.
- **Спроектировано**: `своё` — изменены композиция или действия конкретного шаблона; `общее` — применена рабочая оболочка, навигация и система компонентов без перестройки всей внутренней операции; `redirect` — визуальная поверхность не нужна.
- **Код**: `O` — собственный файл страницы или её содержательного шаблона изменён; `S` — экран изменён через общую оболочку/CSS/компонент; `W` — неизменённый wrapper использует изменённый шаблон; `—` — отдельная реализация не подтверждена. `O` обозначает прямое изменение, а не автора изменений.
- **Visual real**: `P` — реальные публичные данные/доступное состояние сняты в итоговой серии `after-final`, с заменами `after-licenses-final` и `after-selection-final`; `C` — дополнительно сняты и просмотрены commerce-снимки; `нет` — рабочий экран не был открыт с реальной авторизованной сессией. Наличие PNG само по себе не является заключением о художественном качестве каждого экрана.
- **Functional actual** — реально выполненные HTTP/браузерные действия или отдельно названные тесты реального серверного кода на изолированных БД. **Mock** — браузерный перехват ответа API; он не проверяет разрешение сервера, выпуск документа, платёж или доставку письма.

## Что подтверждено в commerce и административной навигации

1. Каталог стал редакционным списком с настоящими названиями, условием записи, направлением и CTA. Поиск применяется явной кнопкой; query сохраняет q/direction/city/format, сброс даёт путь из пустого результата. Направление сравнивается с `directionId`, а не ID программы. «Открыта запись» требует открытой опубликованной версии.
2. Паспорт перестроен: вводная, содержание, результат, документы и ограничения отделены от выбора версии/стоимости/следующего действия. Выбор записывается одним переходом в URL; auth, оплата и корпоративный путь получают тот же versionId. Desktop aside становится sticky только при достаточной высоте экрана; на телефоне блок идёт сразу после вводной. Ценовой CSS ограничен паспортом/заказом и не перезаписывает цену главной.
3. Catalog/program refresh перенесён с `onMounted` в `onNuxtReady`: во время hydration Nuxt мог повторно брать prerender payload и не обращаться за свежими published версиями. После исправления сетевой GET наблюдался в браузере. Механизм не меняет серверный каталог.
4. Auth forgot/verify/reset callback используют безопасный returnTo. SSR initial href не включает недоступный серверу hash; после hydration ссылке возвращается полный клиентский путь. Двойной навигации при выборе версии нет.
5. Оплата сохраняет выбранный вариант при возврате; pending использует реактивный ключ заказа. Статус «оплачено» и переход в обучение зависят от серверного заказа; данные или результат оплаты не синтезируются в UI.
6. Организация принимает versionId только при совпадении с открытой версией каталога, показывает источник выбора, ошибку каталога или недоступность варианта. Ручная смена выбора не оставляет ложной надписи, что исходный вариант по-прежнему выбран.
7. Общий `EditorialAdminNav` не требует props, монтируется `LmsShell` только для admin surface, использует существующий `lms-me`, фильтрует ссылки по прежним ролям и ставит `aria-current`. В mobile разделы раскрываются одной кнопкой и закрываются при переходе. Старый дублирующий nav удалён из `/admin`; девять административных маршрутов получают одинаковые правила формы/таблицы/состояния через `editorial-lms.css`.

## Оставшиеся существенные ограничения

1. **Авторизованное визуальное и E2E покрытие отсутствует.** Изолированная fixture БД подготовлена, но запуск отдельного процесса с `OT_DATABASE_PATH` отклонила автоматическая проверка выполнения. Обход не предпринимался. Кабинет с назначениями, урок, экзамен, документы владельца, организация и работающие admin не могут иметь статус browser verified. Synthetic nav не снимает это ограничение.
2. **Локальное состояние ограничивает commerce.** API имеет 20 направлений и 0 опубликованных версий; email delivery выключена. Реальный published checkout/free enroll, email cycle и последующее обучение/документ не проверены. Это описание окружения, а не заявление о дефекте сервера.
3. **Визуальная проверка всех вариантов содержания не равна проверке шаблонов.** Финальная серия покрывает 36 типов/состояний на двух языках, включая рабочую публичную навигацию, все шаги подбора и UI kit. Отдельные городские/content комбинации за пределами списка capture изучены по исходникам, но не все 558 URL имеют собственный снимок. Это не отменяет подтверждённые реальные public regression результаты.

После code freeze новые продуктовые правки этим исполнителем не выполняются; текущая матрица учитывает финальные сырые QA отчёты и адресный context-final проход. Предыдущие неуспешные прогоны сохранены как история и не выдаются за актуальные дефекты.
