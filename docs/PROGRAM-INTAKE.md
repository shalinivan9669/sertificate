# Program intake control

Migration `008-program-intake.sql` adds `program_intake_controls` separately from immutable program versions. A missing control row or `is_open=1` means intake is open; `is_open=0` stops new intake for that exact version. The published content, revision, review evidence, publication date and historical enrollments remain unchanged.

`POST /api/v1/admin/program-versions/:id/intake` accepts exactly `{ open: boolean, reason: string }`. A current administrator with verified session MFA is required. The reason is trimmed and must contain 10–2000 characters. Only published versions can be controlled. The write and `program.intake_closed` / `program.intake_opened` audit event commit together; a repeat of the same state is idempotent. The actor role is checked again inside the transaction.

Fresh checks run inside each new creation transaction for self enrollment, staff enrollment, organization assignment, individual order and corporate invoice. A stopped version returns `409 PROGRAM_INTAKE_CLOSED`. The exact existing idempotency key continues to return the already created result. Existing lessons, exam attempts, practice confirmations, issued-order/invoice obligations, document issuance, repair and reissue do not consult this creation guard. Intake control does not revoke access.

Both public catalog endpoints keep the version visible and return `intakeOpen`. They use a bounded SQL join rather than one query per version. The private operator reason is not included. A stopped version still displays its curriculum and consultation link; it does not display a new-enrollment or new-order action. A stale browser remains protected by the server transaction guard. Administrators select the exact published version and the desired intake state, enter a reason and explicitly confirm the action in `/admin`.

`tests/program-intake.test.ts` covers authorization/MFA/reason, immutable publication, public visibility without private reasons, all five creation boundaries, exact idempotent replays, continued existing lesson completion, reopening and confirmation of a corporate invoice issued before the stop. `tests/document-pilot-browser.mjs` also stops intake through UI after an existing learner enrolls, runs learning/practice/exam/document recovery/reissue while closed, and reopens intake through UI at the end. Deployment and rollback must account for writer compatibility: an old application artifact that ignores `program_intake_controls` can admit new learners into a stopped version. A database-compatible old schema alone is insufficient evidence for a safe live write rollback. Use a compatible application artifact or disable writes until compatibility is established.
