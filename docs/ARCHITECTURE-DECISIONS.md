# OT Center: архитектурные решения

## ADR 001: существующий Nuxt и текущий дизайн

Владелец просит развить OT Center, сохранив публичные адреса и HomePageClassic. Оставлены Nuxt/Nitro, Tailwind и светлая композиция главной. Новый кабинет, каталог, уроки и админка используют тот же default layout и локальные компоненты. Исторический `nuxt-redesign` не импортируется runtime. Сервер не читает passed/paid/issued из старой cookie.

## ADR 002: бюджет и постоянные данные

Уточнение владельца: бесплатный Vercel, без платных серверов. Отдельный постоянно работающий Node/worker и локальная SQLite в Vercel отвергнуты. Реализован async libSQL: локальный файл только development/tests; удалённый Turso-compatible endpoint для serverless. `VERCEL` без remote URL/token возвращает 503 для операций сохранения, никогда не переключается на `/tmp`/cookie/in-memory database. Аккаунт и удалённая БД автоматически не создаются.

На 07.09.2026 публичный [тариф Turso Free](https://turso.tech/pricing) предусматривает бесплатную квоту. Приложение не подключает платный план/overages. Фактический остаток квот неизвестен до подключения аккаунта. [Vercel Hobby](https://vercel.com/docs/plans/hobby) ограничен личным некоммерческим использованием: совместимость по ресурсам не является разрешением коммерческого выпуска. Деплой не выполнялся.

Реализованы короткие транзакции и lease/outbox. Worker обрабатывает ограниченный batch; CRM/auth requests могут продолжить конкретную запись через Nitro `event.waitUntil`, данные уже сохранены. Cron не чаще одного раза в сутки. Дедлайн экзамена проверяется при каждом чтении/сохранении/submit и отдельной expiry job; он не зависит от точности бесплатного cron. Автосохранение отправляет изменённые ответы, секундный таймер не обращается в БД.

БД хранит текстовые материалы, версии, назначения, результаты и небольшие итоговые PDF (до 1.5 MB каждый). Видео не загружаются в Vercel Functions/БД: владелец задаёт допустимые HTTPS источники с текстовыми альтернативами. Малые документы хранятся приватно в БД ради отсутствия обязательного платного object storage; рост объёма контролируется перед массовым использованием.

## ADR 003: идентичность и права

Better Auth 1.7.3 + официальный Drizzle adapter выполняет пароли, проверку почты, reset и сессии. Самостоятельные алгоритмы аутентификации не вводятся. Привилегированные операции требуют текущую роль из БД и доказательство MFA конкретной сессии. Автор версии не утверждает свою редакцию; опубликованная версия неизменяема. Присоединение к организации — только одноразовое приглашение на подтверждённую почту, не введённый БИН.

## ADR 004: обучение и коммерческие условия

Направление каталога и утверждённая версия программы — разные сущности. Девять legacy направлений импортируются без учебных результатов. Методист создаёт материалы/вопросы/правила, второй ответственный публикует версию. Enrollment фиксирует version ID, прогресс и экзамен на сервере. Практику подтверждает другой уполномоченный инструктор с основанием.

Поддерживаются `free`, `manual`, `paid`: бесплатная опубликованная версия доступна самостоятельной записи, ручной доступ подтверждается сотрудником, оплачиваемый открывается после подтверждённой серверной операции. Организационное назначение создаётся в `pending_access`; наличие membership само не оплачивает курс. Цена, валюта и условия заказа фиксируются сервером в момент создания.

Момент реальной оплаты/состав услуги/пересдачи/возврата владелец пока отдельно не указал. Поэтому `OT_PAYMENT_PROVIDER=disabled` и `OT_PAYMENT_TERMS_APPROVED=0` по умолчанию. Реализованный sandbox — изолированный проверочный адаптер с HMAC webhook, timestamp, merchant/amount/currency checks и идемпотентностью; он не принимает деньги и запрещён в Vercel production. Конкретный боевой провайдер не выдуман.

## ADR 005: документы

По указанию владельца наличие разрешений принято как подтверждённое, юридическое лицо/реестры не проверяются. Выпуск технически требует подтверждённую личность, опубликованную версию, обязательные уроки/практику, серверный успешный результат, договорные условия и действие issuer с MFA/основанием. Владелец загружает реальный PDF AcroForm шаблон и шрифт; другой reviewer утверждает шаблон. Приложение не рисует печати/подписи и не импортирует старые demo сертификаты.

Номер резервируется один раз; retry PDF продолжает тот же credential. Файл становится доступным после успешного формирования. Download защищён ownership, проверка по 256-bit opaque token отдаёт минимальные сведения без ФИО/контактов. Отзыв/переоформление сохраняют историю. Реестр обозначен как внутренний реестр OT Center.

## ADR 006: безопасный запуск

Production-деплой, реальные платежи и массовые уведомления требуют отдельного разрешения владельца. Настройки SMTP/CRM только server env. Проверочные данные создаются исключительно отдельным тестовым скриптом при `OT_APP_ENV=test`; штатные миграции не создают известных пользователей, утверждённые фиктивные программы или сертификаты.
